# Famxplor Family Travel API

> The first API dedicated to family travel. Curated, kid-tested activities and family
> travel-blog posts, geo-searchable worldwide by coordinate and radius, plus a route
> travel-time calculator. Sold as a paid REST API ($4.99–$124.99/month by monthly call
> quota, Enterprise on quote, 14-day trial with no card). Authentication is a single
> static API key in the `api-key` request header. Four operations, all under /v1/.
>
> GENERATED by API Evangelist from the provider's own OpenAPI 3.1.0 document and public
> pages on 2026-09-07. Famxplor serves no llms.txt of its own — https://famxplor.com/llms.txt
> and https://api.famxplor.com/llms.txt both return 404.

## API

## Operations

- `POST /v1/nearest-activities` — `nearest_activities_v1_nearest_activities_post`. Body `{lat, lon, max_distance}` (max_distance in metres, 0–100000, default 1000). Returns up to 100 activities: `{id, title, url, img_url, lat, lon, tags[]}`.
- `POST /v1/nearest-posts` — `nearest_posts_v1_nearest_posts_post`. Same body. Returns up to 100 family travel-blog posts: `{id, title, url, img_url, lat, lon}`.
- `GET /v1/activities/details/{activity_id}` — `activity_details_v1_activities_details__activity_id__get`. Returns the full activity: `{activity_id, name, type, url, description, country, region, city, lat, lon, posts[]}`, where each embedded post carries `what_did` and `enjoyed` — what a real family did there and what they liked. 404 when the id is unknown.
- `POST /v1/travel-time` — `travel_time_v1_travel_time_post`. Body `{locations: [{lat,lon}, …]}`, minimum two; first is the origin, last the destination, the rest are waypoints. Returns `{time (seconds), length_mi, length_km}`.

## How to call it

```bash
curl -X POST "https://api.famxplor.com/v1/nearest-activities" \
  -H 'Content-Type: application/json' \
  -H "api-key: $API_KEY" \
  -H 'Accept-Language: fr' \
  -d '{"lat":48.85341,"lon":2.3488,"max_distance":100000}'
```

- Get a key at https://famxplor.com/api (signup at https://famxplor.com/login).
- `Accept-Language` takes a two-letter ISO 639 code and defaults to `en`; unavailable languages fall back to English.
- Ignore unknown response fields — the provider states new properties may be added.
- Errors are FastAPI-shaped, not RFC 9457: `{"detail": "<string>"}` on 403/404 and `{"detail": [{loc, msg, type}, …]}` on 422.

## What this API does NOT have

Stated so an agent does not go looking. There is no pagination (results cap at 100 per
coordinate), no list-by-city/country/tag operation, no way to enumerate the catalog, no
`getPost` operation (post ids are returned but unusable), no webhooks or event stream, no
OAuth or scopes, no rate-limit response headers, no documented 429, no status page, no
changelog, no deprecation policy, no SDK in any language, and no `/.well-known/` documents.

## Agent surface

- [MCP server (first-party, self-hosted)](https://github.com/alt250/famxplor-family-travel-mcp-server): one tool, `search_family_activities`, wrapping `/v1/nearest-activities`. Run it yourself — `uv sync` then `FAMXPLOR_API_KEY=… uv run server.py`. There is NO hosted MCP endpoint; mcp.famxplor.com and api.famxplor.com/mcp both 404.
- No A2A agent card is published (`/.well-known/agent-card.json` and `/.well-known/agent.json` 404 on every host).
